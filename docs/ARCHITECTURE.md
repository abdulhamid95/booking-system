# ARCHITECTURE — نظام إدارة الحجوزات

هذا المشروع مبني كـ Headless SaaS.
يعني أن النظام مقسوم إلى جزأين رئيسيين:

1. Backend
2. Frontend

الـ Backend مسؤول عن منطق الأعمال، قاعدة البيانات، المصادقة، الصلاحيات، وإدارة الـ API.

الـ Frontend مسؤول عن واجهات المستخدم، لوحة التحكم، وصفحات الحجز العامة، وتجربة الاستخدام.

## مكونات النظام

### Backend
- Django
- Django REST Framework
- قاعدة البيانات
- منطق الحجز
- إدارة الخدمات
- إدارة الموظفين
- إدارة الحجوزات
- المصادقة والصلاحيات
- واجهات برمجية API

### Frontend
- واجهات المستخدم
- لوحة تحكم صاحب المنشأة
- صفحات الحجز العامة للعميل
- التكامل مع الـ API


## لماذا اخترنا Headless SaaS؟

- لأنه يسمح بفصل الواجهة الأمامية عن الخلفية
- لأنه يسهل العمل مع مستقلين أو فريق خارجي
- لأنه يجعل الـ Backend قابلًا للاستخدام من أكثر من واجهة مستقبلًا
- لأنه يناسب أسلوب العمل في هذا المسار:
  - Claude يبني الخلفية
  - والمستقل يبني الواجهة الأمامية
- لأنه يجعل المشروع أوضح من ناحية المسؤوليات بين كل جزء


## توزيع الأدوار في المشروع

### Claude
- يساعد في بناء الـ Backend
- يشارك في كتابة النماذج
- يشارك في بناء الـ API
- يشارك في التوثيق والتنظيم

### المستقل
- يصمم الواجهات
- يبني Frontend متصلًا بالـ API
- يحول الشاشات والتدفقات إلى تجربة استخدام حقيقية


## تدفق العمل داخل النظام

1. العميل أو صاحب المنشأة يتفاعل مع الواجهة الأمامية
2. الواجهة الأمامية ترسل طلبًا إلى الـ API
3. الـ Backend يعالج الطلب
4. يتم التحقق من البيانات أو الصلاحيات
5. يتم التعامل مع قاعدة البيانات
6. يعيد الـ Backend استجابة JSON
7. تعرض الواجهة الأمامية النتيجة للمستخدم
